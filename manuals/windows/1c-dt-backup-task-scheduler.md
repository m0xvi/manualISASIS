## 0. Диагноз: что не так в типовом скрипте

Исходник, с которым приходят чаще всего:

```bat
"%EXE_1C%" DESIGNER /F "%DB_PATH%" /N "%DB_USER%" /P "%DB_PASS%" /DumpIB "%FILENAME%" /Out "%LOG_FILE%" -NoTruncate
if %ERRORLEVEL% EQU 0 (echo Backup success! >> "%LOG_FILE%") else (echo Backup FAILED! >> "%LOG_FILE%")
```

| # | Что в скрипте | К чему приводит | Как исправить |
|---|---|---|---|
| 1 | **Нет `/DisableStartupDialogs`** | Главная причина зависаний. Любая нештатная ситуация — ошибка в командной строке, база не найдена, неверный пароль, нет лицензии, «Конфигурация базы данных не соответствует сохранённой» — вызывает **модальный диалог**. Задача выполняется в неинтерактивной сессии, диалог никто не видит и не закрывает → `1cv8.exe` висит вечно. Документация 1С описывает ровно этот сценарий: ключ позволяет «исключить появление сложно обнаруживаемых „зависаний“: когда конфигуратор формировал диалог выбора параметра, который был недоступен для интерактивного управления». Доступен с платформы **8.3.3** | Добавить `/DisableStartupDialogs` |
| 2 | **Нет `/DisableStartupMessages`** | Стартовые предупреждения («Конфигурация БД не соответствует сохранённой конфигурации. Продолжить?», предупреждения про справку/HTML) — тоже диалоги | Добавить `/DisableStartupMessages` |
| 3 | **`%FILENAME%` строится из `%date%`** | `%date%` зависит от региональных настроек **учётной записи, под которой выполняется задача**: у одной учётки `16.11.2026`, у другой `Sun 11/16/2026`. Слэш `/` в имени файла недопустим → `DumpIB` падает. Отсюда «то работает, то нет» после смены учётки задачи или региональных настроек | Метка времени из PowerShell: `Get-Date -Format yyyyMMdd_HHmmss` |
| 4 | **Имя файла одно на весь день** | Повторный запуск перезаписывает файл; если он открыт/заблокирован (проводник, антивирус, прошлая копия) — выгрузка падает | Уникальное имя с меткой времени до секунд |
| 5 | **Один файл и для `echo`, и для `/Out` 1С** | cmd пишет в OEM (CP866), 1С — в UTF-8: в журнале каша; плюс два писателя в один файл | Разделить: `wrapper.log` и `1c_<метка>.log` |
| 6 | **Успех определяется только по `%ERRORLEVEL%`** | Код возврата 1С — не гарантия: файл может отсутствовать или быть нулевым. Если путь к `1cv8.exe` неверен, cmd даёт код **9009** («не является внутренней или внешней командой»), а в журнале это выглядит как обычный FAILED | Проверять код возврата **и** существование/размер `.dt`, **и** журнал 1С |
| 7 | **Версия платформы зашита в путь** | После обновления платформы каталог меняется → скрипт молча перестаёт работать. Заодно проверьте саму строку: нумерация платформы обычно `8.3.x.y`, вариант `8.5.1.1529` похож на опечатку в `8.3.5.1529` — посмотрите, что реально лежит в `dir /b /ad "C:\Program Files\1cv8"` | Проверка существования + автовыбор свежей версии |
| 8 | **Нет ротации и контроля места** | Каталог backups растёт, диск заполняется → выгрузка начинает падать «через раз» | `forfiles` / `Remove-Item` по возрасту + проверка свободного места до старта |
| 9 | **Нет таймаута и уборки зависших процессов** | Зависший конфигуратор держит экземпляр задачи; при настройке по умолчанию «не запускать новый экземпляр» следующие запуски **пропускаются** — это и есть «работает через раз» | Таймаут с `Kill()`, убийство прошлых `DumpIB`-процессов до старта, лимит времени в задаче |
| 10 | `set "DB_PATH=...";` — точка с запятой после кавычки | **Не ломает ничего**: в конструкции `set "var=value"` cmd игнорирует всё, что стоит после последней кавычки. Но читается как ошибка — лучше убрать | Убрать `;` |
| 11 | Пароль 1С текстом в скрипте, учётка `Admin` | Любой с доступом к файлу читает пароль; учётка администратора ИБ со слабым паролем | Пароль в отдельный файл с ACL, отдельный пользователь 1С для бэкапов |

Проверить, какие процессы 1С сейчас висят и кто их запустил:

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.Name -like '1cv8*.exe' } |
  Select-Object ProcessId, CreationDate, Name, CommandLine | Format-Table -AutoSize -Wrap
```

## 1. Минимально исправленный .cmd

Готовый файл: [`scripts/windows/1c-dt-backup-min.cmd`](../../scripts/windows/1c-dt-backup-min.cmd). Это ваш же подход (чистый cmd, без зависимостей), но с пунктами 1–9 из таблицы выше. Ключевые места:

```bat
for /f "usebackq delims=" %%i in (`powershell -NoProfile -Command "Get-Date -Format yyyyMMdd_HHmmss"`) do set "TS=%%i"
set "DT=%BACKUP_DIR%\Backup_%BASE_NAME%_%TS%.dt"
set /p DB_PASS=<"%SECRET_FILE%"

powershell -NoProfile -Command "Get-CimInstance Win32_Process | Where-Object { $_.Name -like '1cv8*.exe' -and $_.CommandLine -like '*DumpIB*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }"

"%EXE_1C%" DESIGNER /F"%DB_PATH%" /N"%DB_USER%" /P"%DB_PASS%" /DumpIB"%DT%" /Out"%OUT1C%" -NoTruncate /DisableStartupDialogs /DisableStartupMessages
```

и проверка результата не только по коду:

```bat
set "OK=1"
if not "%RC%"=="0" set "OK=0"
if not exist "%DT%" ( set "OK=0" ) else ( for %%F in ("%DT%") do if %%~zF LSS %MIN_SIZE% set "OK=0" )
```

Замечания по cmd-версии:

- сообщения намеренно латиницей: файл в UTF-8 в консоли с OEM-кодировкой даёт нечитаемый текст. Нужен русский — сохраните `.cmd` в CP866 или поставьте первой строкой `chcp 65001 >nul`;
- `set /p DB_PASS=<файл` читает **первую строку** файла — пароль кладётся в файл без лишних пробелов и пустых строк;
- таймаута у чистого cmd нет: его обеспечивает «Останавливать задачу, если она выполняется дольше» в Планировщике (раздел 3). Учтите, что Планировщик убивает процесс задачи, а дочерний `1cv8.exe` может выжить — поэтому убийство `DumpIB`-процессов в начале следующего запуска обязательно;
- версия платформы задаётся явно; проверьте её существование строкой `if not exist "%EXE_1C%"`.

## 2. Рекомендуемый вариант: PowerShell + Планировщик

Файлы в репозитории:

- [`scripts/windows/1c-dt-backup.ps1`](../../scripts/windows/1c-dt-backup.ps1) — основной скрипт;
- [`scripts/windows/1c-dt-backup.cmd`](../../scripts/windows/1c-dt-backup.cmd) — обёртка для тех, кому удобнее запускать `.cmd`.

Что умеет по сравнению с батником: автовыбор самой свежей версии платформы, предпроверки (экзешник, каталог базы, место на диске, файл пароля), убийство зависших `DumpIB`-процессов, запуск через `System.Diagnostics.Process` с **таймаутом и `Kill()`**, проверка результата по коду возврата + размеру `.dt` + журналу 1С (UTF-8), ротация копий и журналов, запись в журнал событий, режим `-ShowOnly` (показать командную строку с замаскированным паролем и не запускать), разные коды возврата для разных сценариев отказа.

### Развёртывание

1. Создайте каталог и скопируйте скрипты:

```powershell
New-Item -ItemType Directory -Force -Path C:\Scripts | Out-Null
Copy-Item 1c-dt-backup.ps1, 1c-dt-backup.cmd C:\Scripts\
```

2. Положите пароль 1С в отдельный файл и закройте его правами (подробнее — раздел 7):

```powershell
Set-Content -Path C:\Scripts\1c-backup-secret.txt -Value '<ПАРОЛЬ_ПОЛЬЗОВАТЕЛЯ_1С>' -NoNewline -Encoding ASCII
icacls C:\Scripts\1c-backup-secret.txt /inheritance:r
icacls C:\Scripts\1c-backup-secret.txt /grant:r "SYSTEM:(F)" "Administrators:(F)" "DOMAIN\svc-1c-backup:(R)"
icacls C:\Scripts\1c-dt-backup.ps1 /inheritance:r
icacls C:\Scripts\1c-dt-backup.ps1 /grant:r "SYSTEM:(RX)" "Administrators:(F)" "DOMAIN\svc-1c-backup:(RX)" "Users:(R)"
```

3. Проверьте, какая платформа установлена и что скрипт находит базу (без запуска выгрузки):

```powershell
Get-ChildItem 'C:\Program Files\1cv8' -Directory | Where-Object Name -match '^\d+\.\d+\.\d+\.\d+$' | Sort-Object { [version] $_.Name } -Descending | Select-Object -First 3 Name
powershell -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\1c-dt-backup.ps1 -BasePath "E:\1C_Base\1cv8\Trade" -BackupDir "D:\Backups\1C" -ShowOnly
```

4. Один контрольный запуск вручную и проверка журнала:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\1c-dt-backup.ps1 -BasePath "E:\1C_Base\1cv8\Trade" -BackupDir "D:\Backups\1C" -User backup -SecretFile C:\Scripts\1c-backup-secret.txt -TimeoutMinutes 120 -KeepDays 14
Get-Content D:\Backups\1C\logs\backup_*.log -Tail 30
```

5. Действие в задаче Планировщика — **напрямую в powershell.exe**, без прослойки `.cmd`:

```
Программа:  C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
Аргументы:  -NoProfile -ExecutionPolicy Bypass -File "C:\Scripts\1c-dt-backup.ps1" -BasePath "E:\1C_Base\1cv8\Trade" -BackupDir "D:\Backups\1C" -User "backup" -SecretFile "C:\Scripts\1c-backup-secret.txt" -TimeoutMinutes 120 -KeepDays 14
Рабочая папка: C:\Scripts
```

Коды возврата скрипта: `0` — успех, `2` — сработал таймаут (процесс убит), `3` — ошибка предпроверок, `4` — выгрузка не подтверждена (код 1С, размер файла или строки «Ошибка» в журнале). Их видно в столбце «Результат последнего выполнения» задачи.

> Параметр `-PlatformVer` фиксирует конкретную версию платформы, если автовыбор свежей нежелателен (например, база обновляется только вместе с регламентными процедурами). Параметр `-BaseServer "srv\ref"` — для клиент-серверной базы вместо `-BasePath`. Параметр `-UcCode` — код разрешения установки соединения (раздел 5).

`-BackupDir` должен быть **локальным** каталогом (не UNC): проверка свободного места опирается на `DriveInfo`, а выгрузка на сетевой ресурс медленнее и чувствительнее к обрывам. Сначала пишем `.dt` на локальный диск, затем вывозим копией (`robocopy`, раздел 6).

## 3. Настройка задачи Планировщика

Именно здесь живёт «работает через раз»: зависший конфигуратор держит экземпляр задачи, а настройки по умолчанию не дают запустить новый.

| Где | Что поставить | Почему |
|---|---|---|
| Общие → «Выполнять вне зависимости от того, зарегистрирован пользователь или нет» | Включено | Ночной запуск без входа в систему. **Следствие:** сессия неинтерактивная, диалоги невидимы → `/DisableStartupDialogs` обязателен |
| Общие → «Выполнять с наивысшими правами» | По ситуации | Нужно, если каталоги базы/копий требуют прав администратора |
| Учётная запись | Та, под которой 1С гарантированно получает лицензии, и у которой есть права **Вход в качестве пакетного задания** (`secpol.msc → Локальные политики → Вход в систему`) | Без этого права задача не стартует, результат `2147943785` (`0x80070569`). После смены пароля учётки задачу нужно пересохранить — иначе она тихо перестаёт работать |
| Триггеры → «Ежедневно», время | Ночное окно, когда в базе нет пользователей | Выгрузка под нагрузкой идёт дольше и может получить блокировки |
| Параметры → **«Останавливать задачу, если она выполняется дольше»** | **2 часа** (по умолчанию — 3 суток!) | Иначе зависший конфигуратор висит днями и блокирует следующие запуски |
| Параметры → **«Если задача уже выполняется»** | **«Остановить существующий экземпляр»** (по умолчанию — «Не запускать новый экземпляр») | Ключевая настройка против «через раз»: новый запуск прибьёт зависший |
| Параметры → «Пробуждать компьютер для выполнения задачи» | Включено | Иначе ночной запуск на уснувшем сервере/ПК пропускается |
| Параметры → «Запускать только при питании от электросети» | Снять | На ноутбуках задача молча не стартует от батареи |
| Параметры → «Запускать задачу как можно скорее, если пропущен плановый запуск» | Включено | Пропущенный запуск выполнится при первой возможности |
| Параметры → «Перезапускать задачу в случае сбоя» | Каждую 1 минуту, до 3 попыток | Разовые сетевые/дисковые сбои не теряют бэкап |

Включите историю задач, иначе причины пропусков не видны: `Планировщик заданий → правая панель → «Включить журнал всех задач»` (журнал `Applications and Services Logs → Microsoft → Windows → TaskScheduler → Operational`).

Полезные команды:

```bat
schtasks /query /tn "1C Backup DT" /v /fo LIST
schtasks /run   /tn "1C Backup DT"
schtasks /end   /tn "1C Backup DT"
```

Типовые коды в «Результат последнего выполнения»:

| Код | Что значит |
|---|---|
| `0x0` | Успех |
| `0x41301` | Задача **уже выполняется** — именно так выглядит блокировка зависшим конфигуратором |
| `0x41303` | Задача ещё ни разу не выполнялась |
| `0x800710E0` | Запуск отклонён из-за условий (питание от батареи, пользователь не зарегистрирован и т. п.) |
| `2147943785` / `0x80070569` | Учётной записи не дано право «Вход в качестве пакетного задания» |
| `0x1`, `0x2`, `0x3`, `0x4` | Код возврата самого скрипта (см. раздел 2) |
| `9009` | Не найден исполняемый файл — неверный путь к `1cv8.exe` |

## 4. Зависшие конфигураторы: почему висят и как убирать безопасно

**Почему висят.** Конфигуратор в пакетном режиме при любой неопределённости показывает модальный диалог: выбор базы, аутентификация, «конфигурация не соответствует», предупреждение о лицензии, блокировка соединений, «продолжить?». В неинтерактивной сессии окна нет — есть процесс, который ждёт нажатия кнопки. Плюс такие процессы держат блокировку файловой базы, и пользователи получают «информационная база заблокирована».

**Что делать сейчас.** Убивать только те процессы, которые относятся к выгрузке (в их командной строке есть `DumpIB`) — сеансы пользователей не пострадают:

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.Name -like '1cv8*.exe' -and $_.CommandLine -like '*DumpIB*' } |
  ForEach-Object { "kill $($_.ProcessId) started $($_.CreationDate)"; Stop-Process -Id $_.ProcessId -Force }
```

**Чего не делать:** `taskkill /F /IM 1cv8.exe` на рабочей машине убивает всех пользователей 1С без сохранения данных.

**Как предотвратить.** `/DisableStartupDialogs` + `/DisableStartupMessages` (диалогов не будет вовсе: вместо них 1С пишет причину в файл `/Out`), лимит времени выполнения задачи, убийство «зависших» в начале каждого запуска, адекватный таймаут в скрипте.

## 5. Лицензии, блокировка соединений, /UC

Три неочевидные причины ночных отказов:

1. **Лицензия.** Конфигуратору нужна клиентская лицензия. Если лицензии сетевые (hasp-менеджер/сервер лицензий) или привязаны к конкретным рабочим местам, ночью под служебной учёткой лицензия может не выдаваться → диалог → зависание. Проверьте: запустите задачу вручную под той же учёткой и посмотрите, что напишет `/Out`; держите лицензию доступной для учётки бэкапа, а учётку задачи — той же, под которой лицензии получаются.
2. **Пользователи в базе.** Для файловой базы выгрузка при активных сеансах идёт дольше и может упереться в блокировки. Планируйте окно без пользователей; при необходимости блокируйте установку соединений заранее.
3. **Код разрешения установки соединения (`/UC`).** Если в базе задан код разрешения (обычно задают, чтобы ночью никто не мешал регламентным работам), пакетный запуск без `/UC"<код>"` не подключится — и снова диалог. Для скрипта это параметр `-UcCode`; в cmd — `/UC"BACKUP"`.

Отдельно про выбор способа:

- **Файловая база** — `.dt` через `DumpIB` штатен; альтернатива быстрее, но грубее: заблокировать соединения и скопировать `1Cv8.1CD`.
- **Клиент-серверная база** — `.dt` тоже работает, но для больших объёмов правильнее резервное копирование средствами СУБД (полное + журнал транзакций): выгрузка в `.dt` занимает часы и требует места, сравнимого с размером базы.

Антивирус: добавьте в исключения каталог базы и каталог копий — сканирование записываемого `.dt` способно и замедлить выгрузку до таймаута, и заблокировать файл.

## 6. Проверка результата, ротация, контрольное восстановление

Три уровня проверки — все три уже есть в скрипте:

1. **Код возврата** 1С (`0`) и код возврата самого скрипта.
2. **Файл**: существует и больше 1 МБ (нулевой `.dt` — типичный признак «диалог закрылся, выгрузка не шла»).
3. **Журнал 1С** (`/Out`, UTF-8): ищем строки, начинающиеся с «Ошибка», и фразу об успешном завершении выгрузки.

Хвост журналов:

```powershell
Get-Content D:\Backups\1C\logs\backup_*.log -Tail 40
Get-ChildItem D:\Backups\1C\logs\1c_*.log | Sort-Object LastWriteTime -Descending | Select-Object -First 1 | Get-Content -Tail 40
```

Ротация: `-KeepDays 14` удаляет `.dt` старше 14 дней (в cmd-версии — `forfiles -p "%BACKUP_DIR%" -m "Backup_*.dt" -d -%KEEP_DAYS% -c "cmd /c del @path"`).

**Раз в месяц делайте контрольное восстановление** — копия, которую ни разу не восстанавливали, копией не является:

```powershell
"C:\Program Files\1cv8\8.3.22.1709\bin\1cv8.exe" DESIGNER /F"D:\Restore\Test_IB" /N"backup" /P"<пароль>" /RestoreIB"D:\Backups\1C\Backup_Trade_20261116_023000.dt" /Out"D:\Backups\1C\logs\restore_test.log" -NoTruncate /DisableStartupDialogs /DisableStartupMessages
```

Для этого нужна отдельная пустая тестовая база (создаётся через `CREATEINFOBASE`) и место на диске.

Копии стоит вывозить с сервера: `robocopy D:\Backups\1C \\backup-srv\1C$ /MIR /Z /R:2 /W:10` отдельной задачей или облачное хранилище с шифрованием.

## 7. Безопасность: пароль 1С

- Пароль нужен 1С в командной строке (`/P`), поэтому совсем без хранилища не обойтись. Минимально приемлемо: **отдельный файл с паролем**, права только у `SYSTEM`, `Administrators` и учётки задачи (`icacls` — команды в разделе 2). Учётка задачи не должна быть администратором домена.
- Заведите **отдельного пользователя 1С для бэкапов** (права администрирования ИБ нужны для `DumpIB`) со стойким паролем — не используйте `Admin`.
- **Пароль, который засветился** в скрипте, в тикете, в переписке или в системе контроля версий, считается скомпрометированным: смените его и обновите секрет-файл.
- Скрипты и секрет-файл **не коммитят в git**, тем более в публичный репозиторий. В репозитории лежат шаблоны с плейсхолдерами; рабочий экземпляр с реальными путями и секретом живёт только на сервере (`C:\Scripts`).
- Строже: пароль в DPAPI-контейнере, расшифровывается только под учёткой задачи —

```powershell
$sec = Read-Host 'Пароль 1С' -AsSecureString
$sec | ConvertFrom-SecureString | Set-Content C:\Scripts\1c-backup-secret.dat
```

  и в скрипте `$pass = [Runtime.InteropServices.Marshal]::PtrToStringAuto([Runtime.InteropServices.Marshal]::SecureStringToBSTR((Get-Content C:\Scripts\1c-backup-secret.dat | ConvertTo-SecureString)))`. DPAPI-блок расшифровывается только той учёткой, которая его создала, поэтому создавать его нужно под учёткой задачи.
- Ограничьте видимость пароля в логах: скрипт маскирует его при выводе командной строки (`***`), не включайте эхо команд (`@echo off` в cmd-версии уже есть).

## 8. Частые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Висят `1cv8.exe`, копии то есть, то нет | Диалог в неинтерактивной сессии: нет `/DisableStartupDialogs`, либо лицензия, либо блокировка соединений | Ключи подавления диалогов; учётка с доступной лицензией; `/UC"<код>"`; раздел 4 |
| Следующие запуски не происходят | Зависший процесс держит задачу; «не запускать новый экземпляр» + лимит 3 суток | «Остановить существующий экземпляр», лимит 2 часа, таймаут в скрипте |
| В журнале `FAILED`, файл не создан, код 9009 | Неверный путь к `1cv8.exe` (сменилась версия платформы, опечатка в номере) | `dir /b /ad "C:\Program Files\1cv8"`, автовыбор версии, предпроверка |
| Файл не создаётся, в журнале 1С «неверное имя файла» | `%date%` в другой локали дал `/` или пробелы | Метка времени из `Get-Date -Format yyyyMMdd_HHmmss` |
| `.dt` нулевого размера при коде возврата 0 | Диалог был закрыт/подавлен, выгрузка не выполнялась | Проверка размера файла и журнала 1С, а не только кода возврата |
| Задача не стартует, результат `0x80070569` | Нет права «Вход в качестве пакетного задания» | `secpol.msc → Локальные политики → Вход в систему`; пересохранить задачу после смены пароля учётки |
| Ночью «нет свободных лицензий» | Лицензии раздаются интерактивным сеансам, сервер лицензий недоступен | Проверить журнал `/Out`, держать лицензию/пин-код для учётки бэкапа |
| «Информационная база заблокирована» у пользователей утром | Зависший конфигуратор держит блокировку файловой базы | Убить `DumpIB`-процессы (раздел 4), выяснить причину диалога |
| Журнал нечитаем | cmd и 1С пишут в один файл в разных кодировках | Разделить `wrapper.log` и `1c_*.log`; журнал 1С читать в UTF-8 |
| Со временем выгрузки начали падать | Кончилось место, старые `.dt` не удаляются | Ротация `-KeepDays`, проверка свободного места до старта |
| Выгрузка идёт часами и упирается в таймаут | Антивирус сканирует `.dt`, база большая, пользователи работают | Исключения антивируса на каталоги базы и копий, ночное окно, увеличить `-TimeoutMinutes` |
| Русские сообщения в `.cmd` — кракозябры | Файл в UTF-8, консоль в CP866 | Сохранить `.cmd` в CP866 или `chcp 65001 >nul` первой строкой |

## 9. Источники

- 1С, «Обновление платформы 8.3.3» (V8Update): появление ключа **`/DisableStartupDialogs`** — «отключать диалоги выбора информационной базы и аутентификации … при пакетном запуске конфигуратора, особенно если запуск выполняется из другого приложения или службы, появилась возможность исключить появление сложно обнаруживаемых „зависаний“».
- Параметры командной строки «1С:Предприятия»: `/DisableStartupDialogs`, `/DisableStartupMessages`, `/Out <файл> [-NoTruncate]`, `/DumpIB`, `/RestoreIB`, `/UC`, `/N`, `/P`, `/F`, `/S`.
- SS64 / Stack Overflow (dbenham) про `set "var=value"`: всё, что стоит после последней кавычки, игнорируется — поэтому `set "DB_PATH=…";` значение не портит.
- Практика Планировщика заданий: коды `0x41301`, `0x41303`, `0x800710E0`, `2147943785`; настройки «Останавливать задачу, если она выполняется дольше» и «Если задача уже выполняется»; журнал `TaskScheduler/Operational`.
